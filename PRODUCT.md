## Platform

web

## Users

Vietnamese customers browse phones by brand, price, storage and color, maintain a guest or account cart, place COD orders and follow their own orders. Administrators use the separate existing API/WinForms surface.

## Product Purpose

Make product selection and ordering clear while keeping live pricing, availability, ownership and order transitions authoritative in the existing SQL-backed services.

## Operating Context

ASP.NET Core MVC and Razor share PhoneStore.Web with the existing API. Controllers call an in-process IStoreService adapter. Guest carts use localStorage in a later PR. SQL Server QA databases are isolated and generated by the test runner.

## Capabilities and Constraints

Deliver six separate reviewable PRs: foundation, accounts, catalog/home, carts/checkout, orders, browser flows/accessibility. Do not modify existing services, schema, migrations, admin endpoints or WinForms. The user approved new Core interface and MVC adapter files, host integration, form-level duplicate feedback without parsing messages, and a read-only product/variant association check in the adapter before calling the cart service. Never merge without explicit approval.

- State clearly what happened and how the customer can recover.
- Preserve entered form values on validation errors; never return passwords.
